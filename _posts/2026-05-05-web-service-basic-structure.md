# 웹 서비스 기본 구조 정리

모의해킹 공부를 진행하기 전에 웹 서비스가 어떤 구조로 동작하는지 이해하기 위해 네트워크, 웹 서버, WAS, DB, Docker, APM 개념을 정리합니다.

---

## 네트워크 (Network)

네트워크는 전자신호를 통해 통신하는 여러 기기가 서로 데이터를 주고받기 위해 구성한 하나의 통신 망을 의미합니다.

- 네트워크에서 서로 다른 기기가 통신하기 위해서는 주소가 필요합니다.
- 서로 다른 장비끼리 통신하기 위해서는 IP와 Port 같은 주소 정보가 필요합니다.
- 소켓(Socket)은 프로그램이 네트워크 통신을 하기 위해 사용하는 통신 창구입니다.
- 소켓 통신에서는 IP, Port, 프로토콜 정보 등을 이용해 통신 대상을 구분합니다.

### IP

IP는 현실에 비유하면 집주소와 비슷한 역할을 합니다.

- IP에는 현재 IPv4와 IPv6가 있습니다.
- 가장 널리 사용되는 주소 체계는 IPv4입니다.
- IPv4는 32비트의 값을 가집니다.
- 보통 8비트씩 끊어 `0~255` 범위의 10진수로 표현합니다.
- 각 숫자는 점 `.`으로 구분합니다.
- IPv4는 총 32비트의 정보 크기를 가지므로 `2^32`개, 약 43억 개의 고유한 주소를 표현할 수 있습니다.

예시:

~~~text
192.168.0.1
~~~

### Port

Port는 해당 IP 주소로 접근했을 때 어느 입구를 통해 접근할지 구분하는 값입니다.

현실에 비유하면 IP가 건물 주소라면, Port는 그 건물 안의 특정 방 번호나 출입구 번호처럼 이해할 수 있습니다.

예시:

~~~text
192.168.0.1:80
192.168.0.1:443
~~~

## 웹 서비스

웹 서비스는 초기에는 서버에 있는 HTML 문서나 파일을 요청하고 받아오는 방식에서 시작되었습니다.

서버가 직접 화면을 보여주는 것이 아니라, 서버는 HTML, CSS, JavaScript, 이미지 등의 파일이나 데이터를 응답하고, 브라우저가 이를 해석하여 화면에 표시합니다.

즉, 사용자가 웹 사이트에 접속하면 다음과 같은 흐름이 발생합니다.

1. 사용자가 브라우저에서 웹 사이트에 접속합니다.
2. 브라우저가 서버에 HTTP 요청을 보냅니다.
3. 서버는 메인 페이지에 필요한 HTML, CSS, JavaScript, 이미지 등의 파일을 응답합니다.
4. 브라우저는 응답받은 파일을 해석하여 화면에 표시합니다.

---

## 일반적인 웹 서비스 구성

일반적인 웹 서비스는 웹 서버, WAS, DB를 중심으로 구성할 수 있습니다.

| 구성 요소 | 역할 |
|---|---|
| 웹 서버 (Web Server) | 정적 파일을 제공하거나 동적 처리가 필요한 요청을 WAS로 전달 |
| WAS (Web Application Server) | 요청을 처리하고 DB와 연동하여 동적 응답 생성 |
| DB (Database) | 회원 정보, 게시글, 주문 내역 등 데이터를 저장하고 관리 |

---

## 웹 서버 (Web Server)

웹 서버는 웹 서비스의 구성 요소 중 하나입니다.

클라이언트, 즉 사용자의 브라우저 요청을 받아 웹 페이지나 파일을 응답해주는 서버입니다.

### 주요 역할

- HTML, CSS, JavaScript, 이미지 같은 정적 파일을 제공
- 사용자의 HTTP 요청 수신
- 필요한 경우 동적 처리가 필요한 요청을 WAS로 전달
- 클라이언트에게 응답 반환

### 사용되는 환경

대표적인 웹 서버에는 다음과 같은 것들이 있습니다.

- Apache
- Nginx
- Microsoft IIS

### 정적 파일

정적 파일은 접근하는 사용자마다 내용이 바뀌지 않고, 동일한 내용을 제공하는 파일을 의미합니다.

예시:

- HTML 파일
- CSS 파일
- JavaScript 파일
- 이미지 파일
- 동영상 파일

---

## WAS (Web Application Server)

WAS는 웹 서비스의 구성 요소 중 하나입니다.

웹 페이지에서 필요한 동적 기능과 비즈니스 로직을 처리하는 서버입니다.

### 주요 역할

- 클라이언트 요청에 따라 필요한 데이터를 DB에서 조회
- 사용자가 입력한 데이터를 DB에 저장
- 사용자, 로그인 상태, 요청 값 등에 따라 달라지는 동적 응답 생성
- 처리 결과를 웹 서버 또는 클라이언트에게 전달

### 사용되는 환경

대표적인 WAS 또는 서버 측 런타임/프레임워크에는 다음과 같은 것들이 있습니다.

- Tomcat
- JBoss / WildFly
- WebLogic
- WebSphere
- Node.js
- Django
- Spring Boot

### 동적 기능 예시

- 로그인 처리
- 회원가입 처리
- 게시글 작성
- 장바구니
- 결제 처리
- 사용자별 마이페이지

---

## DB (Database)

DB는 웹 서비스에서 사용되는 데이터를 저장하고 관리하는 공간입니다.

회원 정보, 게시글, 상품 정보, 주문 내역 등 다양한 데이터를 저장합니다.

### 주요 특징

- 데이터를 저장하고 관리하는 역할을 합니다.
- 일반적으로 관계형 DB는 데이터를 테이블 형태로 저장합니다.
- 각 데이터는 행과 열로 구성됩니다.
- 특정 데이터를 구분하기 위해 고유값을 사용합니다.
- 이 고유값을 기본키 또는 Primary Key라고 합니다.
- 관계형 DB의 테이블 구조는 엑셀 표와 비슷하게 이해할 수 있습니다.

### 저장되는 데이터 예시

- 아이디
- 해시 처리된 비밀번호
- 회원 정보
- 게시판 글 데이터
- 댓글 데이터
- 상품 정보
- 사용자별 데이터

## Docker

Docker는 웹 서버, WAS, DB 등 서비스 실행에 필요한 환경을 컨테이너 단위로 분리하여 구성할 수 있게 해주는 도구입니다.

### 컨테이너

컨테이너는 애플리케이션과 실행에 필요한 라이브러리, 설정 등을 하나의 독립된 실행 단위로 묶어 관리하는 방식입니다.

### Docker의 장점

- 개발, 테스트, 배포 환경을 쉽게 재현할 수 있습니다.
- 웹 서버, WAS, DB를 각각 분리하여 실행할 수 있습니다.
- 환경 차이로 인한 오류를 줄일 수 있습니다.
- 여러 서비스를 독립적으로 관리할 수 있습니다.

### Docker Compose

Docker Compose를 활용하면 여러 컨테이너를 하나의 설정 파일로 묶어 한 번에 실행하고 관리할 수 있습니다.

예를 들어 다음과 같이 구성할 수 있습니다.

- 웹 서버 컨테이너
- WAS 컨테이너
- DB 컨테이너

---

## APM (Apache - PHP - MySQL)

APM은 Apache, PHP, MySQL을 조합하여 웹 서비스를 구성하는 대표적인 방식입니다.

| 구성 요소 | 역할 |
|---|---|
| Apache | 웹 서버 역할 |
| PHP | 서버 측에서 동적 페이지를 처리 |
| MySQL | 데이터를 저장하고 관리하는 DB 역할 |

APM은 과거부터 PHP 기반 웹 서비스를 빠르게 구성할 때 많이 사용되었습니다.

Docker 등의 도구를 사용하면 APM 환경을 컨테이너 기반으로 빠르게 구성하고 배포할 수 있습니다.

---

## 정리

웹 서비스는 단순히 하나의 서버만으로 동작하는 것이 아니라, 여러 구성 요소가 역할을 나누어 동작합니다.

기본적인 흐름은 다음과 같이 이해할 수 있습니다.

~~~text
사용자 브라우저
    ↓
웹 서버
    ↓
WAS
    ↓
DB
~~~

- 브라우저는 서버에 요청을 보냅니다.
- 웹 서버는 정적 파일을 응답하거나 동적 요청을 WAS로 전달합니다.
- WAS는 필요한 로직을 처리하고 DB와 연동합니다.
- DB는 데이터를 저장하고 조회합니다.
- 처리 결과는 다시 브라우저로 전달되어 화면에 표시됩니다.

이러한 기본 구조를 이해하면 이후 모의해킹 실습에서 요청 흐름, 서버 구조, 인증 처리, 데이터 저장 방식 등을 분석하는 데 도움이 됩니다.

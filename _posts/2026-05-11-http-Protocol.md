## HTTP 란

- HTTP는 HyperText Transfer Protocol의 약자이다.
- HTTP는 웹에서 클라이언트와 서버가 HTML 문서, 이미지, JSON 데이터 등 다양한 리소스를 주고받기 위한 프로토콜이다.
- HTTP는 일반적으로 80 포트를 사용하며, HTTP에 TLS 암호화를 적용한 HTTPS는 일반적으로 443 포트를 사용한다.
	- HTTP : 일반적으로 80 포트를 사용하며, 전송 내용이 평문으로 전달된다.
	- HTTPS : 일반적으로 443 포트를 사용하며, HTTP와 달리 전송 내용이 암호화되어 전달된다.

## HTTP의 버전

- HTTP의 주요 버전에는 HTTP/1.0, HTTP/1.1, HTTP/2, HTTP/3가 있다.
- 현재 일반적인 웹 서비스에서는 HTTP/1.1과 HTTP/2가 널리 사용되며, 일부 서비스에서는 HTTP/3도 사용된다.

## HTTP의 구조

- HTTP는 크게 요청(Request) 과 응답(Response) 으로 구분된다.
- 클라이언트가 요청(Request)을 보내면 서버가 응답(Response)을 하는 구조이다.

### HTTP 요청(Request)

- HTTP 요청의 경우 아래 형태의 구조로 이루어져 있으며, 보통 페이지 요청, 로그인 요청 등이 있다.

#### 형식
~~~
[메서드] [요청파일명] [HTTP 버전]
[헤더 이름]: [헤더 값]
[헤더 이름]: [헤더 값]

[Body 부분]
~~~
#### 예시
~~~
GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
~~~

~~~
POST /login HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 27

username=test&password=1234
~~~

### HTTP 응답(Response)

- HTTP 응답의 경우 클라이언트의 요청에 의한 서버의 응답값 이다.

#### 형식
~~~
[HTTP 버전] [상태 코드] [상태 메시지]
[헤더 이름]: [헤더 값]
[헤더 이름]: [헤더 값]

[Body 부분]
~~~
#### 예시
~~~
HTTP/1.1 200 OK
Date: Mon, 11 May 2026 12:00:00 GMT
Server: nginx
Content-Type: text/html; charset=UTF-8
Content-Length: 58

<html>
  <body>
    <h1>Login Success</h1>
  </body>
</html>
~~~


## HTTP 메서드 종류

1. GET : 클라이언트가 서버에게 URL에 해당하는 자료의 전송을 요청한다.
2. POST : 클라이언트가 서버에 데이터를 전송하여 생성, 처리 등의 작업을 요청한다. 예를 들어 로그인 요청이나 게시글 작성 요청에 사용된다.
3. HEAD : GET 요청으로 반환될 데이터 중 헤더 부분에 해당하는 데이터만 요청한다.
4. PATCH : 지정한 리소스의 일부를 수정할 때 사용한다.
5. PUT : 지정한 리소스 전체를 생성하거나 교체할 때 사용한다.
6. DELETE : 지정한 리소스를 삭제할 때 사용한다.
7. TRACE : 클라이언트가 서버에게 송신한 요청의 내용을 반환해 줄 것을 요청한다.
8. CONNECT : 클라이언트가 특정 종류의 프록시 서버에게 연결을 요청한다.
9. OPTIONS : 해당 URL에서 지원하는 요청 메시지의 목록을 요청한다.

#### HTTP 메서드 속성

| HTTP 메서드 | 안전  | 멱등(Idempotent) | 캐시 가능 |
| :------: | :-: | :------------: | :---: |
|   GET    |  예  |       예        |   예   |
|   POST   | 아니오 |      아니오       |  조건부  |
|   HEAD   |  예  |       예        |   예   |
|  PATCH   | 아니오 |      아니오       |  조건부  |
|   PUT    | 아니오 |       예        |  아니오  |
|  DELETE  | 아니오 |       예        |  아니오  |
|  TRACE   |  예  |       예        |  아니오  |
| CONNECT  | 아니오 |      아니오       |  아니오  |
| OPTIONS  |  예  |       예        |  아니오  |

 \*) 안전 : 호출해도 서버의 리소스 상태를 변경하지 않는 성질이다. 여기서 안전은 보안적으로 안전하다는 뜻이 아니다.<br>
 \*) 멱등성(Idempotent) : 같은 요청을 한 번 보내든 여러 번 보내든, 서버에 의도한 최종 효과가 같은 성질이다.
   안전과 멱등의 차이점
   1. HTTP 메서드의 안전이 한 번 호출하든 여러 번 호출하든 리소스가 수정되지 않는 속성
   2. HTTP 메서드의 멱등은 리소스에 수정이 발생해도 메서드를 여러번 실행한 결과가 한 번 실행한 결과와 같으면 만족한다.
   3. 예를 들어 DELETE /users/1 요청은 처음 호출하면 사용자가 삭제되고, 이후 다시 호출하면 이미 삭제되어 404가 날 수 있다. 응답 코드는 달라질 수 있지만, "해당 사용자가 삭제된 상태"라는 최종 효과는 같으므로 멱등으로 본다.

*HTTP 메서드는 클라이언트가 서버의 리소스에 대해 어떤 동작을 원하는지 표현하기 위한 약속이다.*
*기술적으로는 GET과 POST만으로도 여러 기능을 구현할 수 있지만, 리소스의 조회/생성/수정/삭제 의미에 맞게 GET, POST, PUT, PATCH, DELETE 등을 사용하는 것이 RESTful API 설계에 더 가깝다.*

## HTTP 응답 코드 종류

- HTTP 응답 코드의 경우 표준 응답 코드와 비표준 응답 코드가 있으며, 표준 응답 코드의 경우 1XX, 2XX 식으로 100의 단위가 달라질 때마다 응답의 종류가 다르다.

1. 1XX : 정보 응답
- 서버가 요청을 받았으며, 최종 응답을 보내기 전에 중간 상태를 알려주는 응답이다.
1. 2XX : 성공
- 요청이 정상적으로 처리되었음을 의미한다.
- 주로 200, 201, 204, 206이 주로 사용된다.
1. 3XX : 리다이렉션
- 요청을 완료하기 위해 이동(redirect)해야 함을 의미한다.
1. 4XX : 클라이언트 오류
- 해당 요청에 대해 올바르지 않다는 의미이다.
- 클라이언트의 요청이 잘못되었거나 권한이 없어 처리할 수 없을 때 사용된다.
- 403 Forbidden(거부됨), 404 Not Found(찾을 수 없음) 등을 주로 확인할 수 있다.
1. 5XX : 서버 오류
- 요청 자체는 서버에 도달했지만, 서버가 요청을 처리하는 과정에서 실패했을 때 사용된다.
- 서버 내부 오류, 게이트웨이 오류, 서비스 장애 등이 발생하면 500, 502, 503, 504 같은 상태 코드가 반환될 수 있다.

## HTTP 주요 헤더

- HTTP 헤더에는 여러 종류가 있으며, 기본적인 주요 헤더는 아래 목록과 같습니다.

1. Host: 요청 대상 서버의 도메인
2. User-Agent: 클라이언트 프로그램 정보
3. Cookie: 클라이언트가 서버에 보내는 쿠키 정보
4. Set-Cookie: 서버가 클라이언트에게 저장시키는 쿠키
5. Content-Type: Body 데이터 형식
6. Authorization: 인증 정보 전달
7. Location: 리다이렉션 대상
8. Accept: 클라이언트가 받을 수 있는 응답 데이터 형식
9. Referer: 현재 요청이 이전에 어떤 페이지에서 이동해왔는지 나타내는 정보
